# 利用枠を節約しつつ、開発効率を落とさない 10 手

作業が止まる一番の原因は「高いモデルで同じ探索を繰り返す」こと。
このリポジトリでは、実装できるものは入れた。残りは毎回の使い方。

## 実装済み（この PR）

1. **短いリポジトリ地図を固定する**  
   `AGENTS.md` に触るファイルとコマンドだけ書いた。Agent が毎回ディレクトリを歩き直さない。

2. **巨大データをコンテキストから外す**  
   `.cursorignore` で本番 CSV を除外し、小さい fixture だけ読めるようにした。

3. **小さい fixture で回す**  
   `fixtures/sample-pref.csv` でランキングを再現できる。`npm run start:fixture`。

4. **集計を関数化して単体テストする**  
   `app.js` のロジックを export し、`node --test` で検証する。フル CSV をチャットに貼らない。

5. **コマンドを scripts に固定する**  
   `npm test` / `npm start` / `npm run start:fixture`。Agent がコマンドを発明しない。

6. **探索禁止ルールを置く**  
   `.cursor/rules/quota-efficiency.mdc` で全文読み・余分なサブエージェント起動を止める。

## 運用（ダッシュボード / 毎回の依頼）

7. **同じチャットで続ける**  
   続きの修正は新規 Cloud Agent を立てず、今のスレッドに書く。起動と再探索のコストが消える。

8. **モデルを使い分ける**  
   文言修正・テスト追加は安いモデル。設計や原因不明のバグだけ高いモデル。

9. **Max Mode / 長考は必要なときだけ**  
   このリポジトリの集計変更に長考は不要。オンにするのは方針が割れているときだけ。

10. **依頼を 1 往復にまとめる**  
    目的、完了条件、触ってよいファイル、やってはいけないことを最初の一文に書く。聞き返しと手戻りが減る。

## やらないこと

- 本番 CSV をチャットやルールに貼る
- 毎回新しい Agent に「まず全体を見て」と頼む
- 依存のないこのリポジトリに重い環境構築を足す
